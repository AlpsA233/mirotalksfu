# 仅录音与主动发言

适用于开启服务端托管录制的新会议。所有允许采集麦克风的用户（包括主持人）默认仅录音；未开启服务端录制的会议沿用原来的麦克风行为。

| 操作                      | 会议中的其他人 | 个人录像         |
| ------------------------- | -------------- | ---------------- |
| 入会默认仅录音            | 听不到该用户   | 保留该用户的声音 |
| 开始发言                  | 能听到该用户   | 持续录音         |
| 结束发言 / 主持人静音     | 听不到该用户   | 持续录音         |
| 音频菜单 → 停止麦克风采集 | 听不到该用户   | 停止录入后续声音 |
| 音频菜单 → 恢复仅录音     | 听不到该用户   | 新建音轨继续录音 |

发言切换保持同一条上传音轨。真正停止采集、切换设备或重新入会会创建新的音轨片段，恢复时不会自动发言。主持人邀请发言仍须本人确认。仅录音音频不参与会议主讲人识别。

## 启用与界面

1. 配置 `MANAGED_RECORDING_ENABLED=true`、管理员密码、FFmpeg 和持久化存储。
2. 在 `/recordings` 中开启新会议录制，再创建一个新会议。前端和服务器须一起更新，已打开的旧页面须刷新。
3. 用户允许麦克风采集后看到“仅录音中，其他人听不到”，点击“开始发言 / 结束发言”控制会议发言；音频菜单中可以完全停止采集。

未授权麦克风、设备不可用或录制失败时不显示“录音中”。模式切换请求无法确认时关闭本地采集并提示重试，避免用户误以为已经结束发言。停止采集的选择会保存；自动重新入会使用采集选择，而不是把“没有发言”误判为关闭麦克风。

## 实现与接口

服务器为托管麦克风设置 `audioMode=record_only|live`。只有 `live` 音频可被参会者发现、订阅和恢复接收。`ManagedRecording` 的录制接收端独立于参会者接收端，切换模式不会暂停录制源。

- `setAudioMode({ producer_id, mode })`：请求切换模式，返回服务器确认的状态。
- `audioModeChanged({ peer_id, producer_id, mode, revision })`：同步模式；关闭音频源后模式为 `off`。
- `peer_audio_mode` 表示音频模式；`peer_audio` 表示是否正在会议中发言，不能用于判断录音是否停止。

## 分步验证

自动化测试（Node 24+）：

```sh
npx mocha tests/test-AudioRouting.js tests/test-ManagedAudioClient.js
FFMPEG_PATH=/path/to/ffmpeg FFPROBE_PATH=/path/to/ffprobe node tests/integration/record-only-audio.cjs
npm test
```

真实媒体脚本使用两路不同频率的合成音频，经真实 mediasoup 和 FFmpeg 验证：默认不可订阅、发言期间能收到 RTP、结束发言后停止接收，且两人的个人录音在三个阶段均有有效声音。设置 `KEEP_RECORDING_TEST_ARTIFACTS=1` 可保留文件供排查。

双浏览器验收：两人加入新录制会议，依次测试默认仅录音、发言、结束发言、主持人静音、停止采集和恢复。加入第三个页面，确认其只能听到正在发言的人；下载或回放个人录像，确认仅录音期间也有声音。

iPhone Safari 须使用真机补充上述验收，尤其检查授权、音频播放、切换按钮和停止采集后的麦克风占用。桌面模拟不能代替这项验证。

## 本版范围

本版只验证会议音频隔离与个人录像，不增加机位绑定或合成音源选择。整场合成仍混合全部录制音轨，因此可能包含仅录音期间的声音或同一现场的重复声音。副机位可自行关闭扬声器，避免把会议播放声音再次录入。
